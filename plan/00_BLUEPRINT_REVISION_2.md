## 1. Executive Summary of Blueprint Revision 2

Patroner is an integrated fashion creation, deterministic garment engineering, manufacturing coordination, brand-building, and commerce ecosystem (`v5.16 Ch. 01, p. 5`). Its defensibility lies in the unbroken, evidence-governed continuity of a **Fashion Project** from initial creative inspiration and multimodal AI interpretation through verified anthropometrics, deterministic pattern drafting, multi-size grading, material/fit validation, qualified workshop sampling, production release, order fulfillment, financial reconciliation, and permissioned closed-loop learning (`v5.16 Ch. 05, p. 10; Ch. 07, p. 13`).

An independent source-level and live-product audit of the Patroner repository at commit `e9d99cb4afc54057850f920dc909b23ebde86f1f` established two foundational truths:
1. **The repository is architecturally inverted (`X`) relative to the approved system-of-systems design:** All `70,305` lines of existing code are written in TypeScript inside a client-side React 19 / Vite 8 single-page application (`0` Python files, `0` Next.js routes, `0` server-side API endpoints, `0` database tables). Browser components directly execute drafting, grading, ease, and snapshot logic in volatile memory. Furthermore, the live deployment at `https://patroner.ai.studio/` serves an older static bundle compiled on `07 November 2026` that predates the repository’s Milestone `04.6.2.3.x`, `05.1`, and `05.2.1` trust and lifecycle modules.
2. **The repository contains high-value deterministic engineering assets (`I1`/`I2`/`P`) that must be evaluated as evidence, verified against independent mathematical references, and migrated without reproducing legacy defects:** The TypeScript engines implement substantial 2D computational geometry (exact Green’s theorem contour area, adaptive De Casteljau cubic Bézier arc length, miter/bevel allowance offsetting), parametric bodice/skirt/sleeve drafting, rotational dart manipulation, bodice-sleeve scye/cap assembly validation, `XS`–`XXL` measurement-delta grading (for bodice/sleeve), anisotropic fabric ease and negative-ease authorization policies, and Ed25519/SHA-256 revision/artifact lineage.

**Blueprint Revision 2** corrects the migration and implementation programme so that an engineering team can execute each workload independently without treating legacy TypeScript behavior as normative truth or postponing foundational security, manufacturing, or financial controls.

## 4. Non-Negotiable Architectural & Governance Rules

1. **Authoritative System Boundary (`ADR-001`):** Python owns authoritative fashion-domain computation, deterministic engineering, AI reasoning/orchestration, independent validation/evaluation, canonical artifact generation, and domain workflows. Next.js owns user interaction, presentation, navigation, and client-side viewport behavior.
2. **Evidence-Driven Runtime Topology (`ADR-002`):** Begin with a modular Python monolith and a Next.js application communicating over versioned contracts. Do not split into microservices without workload evidence. Infrastructure choices (PostgreSQL, object storage, background worker queue) are justified with explicit alternatives and exit criteria.
3. **Canonical Fashion World Model (`ADR-003`):** Every project, specification, measurement set, material profile, recipe, pattern revision, grading artifact, simulation case, fit report, production sheet, BOM, sample approval, quote, offer, work order, and financial transaction has stable identity, immutable revision history, guarded current-head pointers, and selective dependency invalidation.
4. **AI Proposes; Deterministic Engines Compute; Validators Verify; Humans Approve (`ADR-004`, `ADR-007`):** AI output never directly becomes trusted geometry, measured anthropometry, fit qualification, or production release.
5. **Strict 8-State Realization Lifecycle & `isProductionReady: false` (`10_RELEASE_AND_GOVERNANCE_POLICY.md`):** The eight states of `v5.16 Chapter 09 (p. 16)` (`Inspiration` → `AI proposal` → `User-approved design` → `Specification in progress` → `Feasibility reviewed` → `Sample approved` → `Production-ready offer` → `In production / fulfilled`) are enforced as non-collapsible state transitions. `isProductionReady` remains `false` on all engineering artifacts until the complete scoped release checklist (`v5.16 Appendix F, p. 41`) is satisfied.
6. **Platform vs Own-Label Neutrality & Financial Truth (`ADR-008`):** Patroner Platform and Patroner’s own fashion label operate as separate tenants and separate P&Ls with documented internal transfer pricing and zero cross-tenant privilege. Every product offer discloses all eight accountable roles (`seller`, `manufacturer`, `payment collector`, `customer support`, `creator compensation`, `defect liability`, `delay liability`, `return/refund liability`).
