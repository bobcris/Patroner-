## 1. Status Taxonomy (Strict Epistemic Definitions)

* **`ACCEPTED`**: Signed off by Project Owner at a formal Governance Gate (`Gate Auth-1`–`Gate Auth-4`). *Strictly zero items below claim `Gate Auth-2` `ACCEPTED` status.*
* **`VERIFIED`**: Implemented on a dedicated git branch, automated verification executed cleanly with deterministic reproducibility and recorded SHA-256 artifact digests; awaiting formal Owner Gate audit (`Gate Auth-2`).
* **`IMPLEMENTED_UNVERIFIED`**: Source implementation exists in codebase (`C0-Legacy` TS prototype or partial scaffold) without full certification/external verification.
* **`BLOCKED`**: Missing prerequisite module, closed Governance Gate (`Gate Auth-2`–`Gate Auth-4`), or unexecuted external qualification.
