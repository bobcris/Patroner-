## 1. Core Verification Philosophy (`R2.1.1`)

1. **Passing Unit Tests Are Necessary But Never Sufficient:** An implementation can pass unit tests while harboring 17× error-bound violations (`DEF-M00-01`), interior cusp bypasses (`DEF-M00-02`), and cross-tenant omission vulnerabilities (`DEF-M00-04`).
2. **Five-Concept Numerical Assurance & Triangle-Inequality Error Enclosure (`Corrections A & B`):**
   - Every numerical validation separates **(1) High-precision reference result ($X_{\mathrm{ref}}$)**, **(2) Observed implementation-to-reference discrepancy ($E_{\mathrm{obs}} = |X_{\mathrm{float64}} - X_{\mathrm{ref}}|$)**, **(3) Certified reference-to-exact enclosure ($B_{\mathrm{ref}} \ge |X_{\mathrm{ref}} - X_{\mathrm{exact}}|$)**, **(4) Certified implementation-to-exact error bound ($B_{\mathrm{cert}} \ge |X_{\mathrm{float64}} - X_{\mathrm{exact}}|$)**, and **(5) Engineering acceptance tolerance ($\tau_{\mathrm{domain}}$)**.
   - By the triangle inequality, $|X_{\mathrm{float64}} - X_{\mathrm{exact}}| \le E_{\mathrm{obs}} + B_{\mathrm{ref}} \le B_{\mathrm{cert}} \le \tau_{\mathrm{domain}}$. The reference-to-exact term $|X_{\mathrm{ref}} - X_{\mathrm{exact}}|$ is **never** silently assumed to be zero.
   - Where $|X_{\mathrm{ref}} - X_{\mathrm{exact}}|$ cannot be bounded rigorously, the check is labeled a `HIGH_PRECISION_NUMERICAL_REFERENCE` (`EMPIRICAL_ESTIMATE`), never a `CERTIFIED_BOUND`.
   - The legacy adaptive Gauss–Legendre quadrature-difference formula $E_{\mathrm{est}} = S_{\mathrm{safety}}\cdot|I_{\mathrm{GL}(n)} - I_{\mathrm{GL}(2n)}|$ with $S_{\mathrm{safety}} = 16.0$ (`Method C1-Est`) is downgraded to a **`CONSERVATIVE_ENGINEERING_ESTIMATE`** (`Correction B`). Certified arc-length bounds use **`Method C1-Cert`** (De Casteljau chord vs. control-polygon convex-hull interval enclosure $\underline{L}_{\mathrm{chord}} \le L_{\mathrm{exact}} \le \overline{L}_{\mathrm{poly}}$ in `mpmath.iv`).
3. **Six-Category Offset Taxonomy & Tri-State Interval Verification (`Corrections C & D`):**
   - Finite point grids (`65-point Gauss–Lobatto`) are fast pre-screening heuristics only.
   - Complete parameter-interval ($t \in [0, 1]$) verification (`Method C3`) independently evaluates all **6 Offset Failure Categories**: `REGULARITY_MARGIN_VIOLATION`, `ACTUAL_ZERO_SPEED_CUSP`, `TANGENT_REVERSAL`, `LOCAL_OFFSET_SELF_INTERSECTION`, `GLOBAL_CONTOUR_SELF_INTERSECTION`, and `INCONCLUSIVE_VERIFICATION`.
   - Every interval check returns one of three explicit states: **`CERTIFIED_VALID`** ($\underline{F} > 0$), **`CERTIFIED_INVALID`** ($\overline{F} \le 0$ or isolated root), or **`INCONCLUSIVE`** ($\underline{F} \le 0 < \overline{F}$ at budget exhaustion). An `INCONCLUSIVE` outcome fails closed at release gates (`is_production_ready = False`) without ever being conflated with a confirmed cusp, tangent reversal, or self-intersection.
4. **Six-Stage Authorization & Release Gate Separation (`Corrections 03 & F`):**
   - Program governance separates **`Gate Auth-1`** (`M00` commencement — currently `BLOCKED`), **`Gate Auth-2`** (`M01`/`M02` authoritative build entry), **`Gate Auth-3`** (`Vertical Slice` internal technical acceptance), **`Gate Auth-4`** (`Release Level A` — `M09` pilot entry), **`Gate Auth-5`** (`Release Level B` — `M09` pilot exit acceptance), and **`Gate Auth-6`** (`Release Level C` — `M10` enterprise-scale release).

| Authorization Gate | Target Milestone Boundary | Scope, Required Approvals & Purpose | Prohibited Conflation |
| :--- | :--- | :--- | :--- |
| **`Gate Auth-1` — Authorization to Begin `M00`** | Entry gate to **`M00` (Migration Prep & Oracles)** | Requires formal approval of `ADR-009`, `DEC-01`, `DEC-13`, and explicit Project-Owner commencement authorization. **Currently `BLOCKED / UNAUTHORIZED`.** | Publishing Blueprint `R2.1.1` does **not** authorize starting `M00` or modifying code. |
| **`Gate Auth-2` — Authorization to Begin `M01`/`M02` Implementation** | Exit of **`M00.10`** / Entry to **`M01` & `M02`** | Certifies `M00` inventory, legacy freeze, Class A/B fixtures, and independent `M00.4` oracle harness are complete; requires workload-specific decisions (`DEC-02`–`06`, `DEC-09`, `DEC-11`) before their respective sub-workloads close. | Does **not** require commercial/tax decisions (`DEC-07`, `DEC-08`, `DEC-10`, `DEC-12`, `ADR-008`) to begin core engineering. |
| **`Gate Auth-3` — Internal Technical Acceptance (`Vertical Slice Gate`)** | End-to-end 14-step Vertical Slice (`M01`–`M06`) | Certifies that the Python engine, Next.js workspace, 5-concept numerical enclosures, tri-state `CERTIFIED_VALID` offset verification, multi-size grading, `M02h` marker nesting, `M05` tech packs, and `M06` simulation/fit loop pass all software gates. | Software vertical slice completion does **not** authorize commercial pilot checkout or set `isProductionReady: true`. |

| **`Gate Auth-6` — Enterprise-Scale Release (`Release Level C`)** | Exit gate of **`M10`** | Certifies repeatable multi-brand/celebrity Brand Studio operations, enterprise partner APIs, automated GDPR crypto-shredding at scale, BYOK KMS, and multi-region disaster recovery (`RPO <= 5 min`, `RTO <= 30 min`). | Governed strictly post-`M09`. |

## 4. Mandatory 24-Section Workload Specification Standard

Every workload file in `/plan/workloads/M00` through `/plan/workloads/M10` includes and satisfies all **24 mandatory sections**:
1. Workload ID & Title  
2. Purpose & Architectural Role  
3. Governing Monograph Chapters, Addenda & Dossiers  
4. Canonical Requirements Implemented (`REQ-*`)  
5. Current Repository Baseline & Classification (`I1`, `I2`, `P`, `D`, `M`, `X`, `R`, `H`)  
6. Residual Defects & Technical Debt to Close (`DEF-*`)  
7. Prerequisites & Upstream Dependencies  
8. Target Architecture & Module Ownership (`services/fashion-engine` vs. `apps/web` vs. `packages/contracts`)  
9. Domain Entities, State Machines & Data Contracts  
10. Mathematical, Algorithmic & Domain Specifications  
11. API Endpoints, Async Jobs & Event Contracts  
12. Security, Tenant Isolation, RBAC/ABAC & Provenance Controls  
13. User Experience & Workspace Surfaces (`apps/web`)  
14. Detailed Work Packages & Implementation Sequence  
15. Migration & Parity Strategy (Class A vs. Class B Fixtures)  
16. Unit, Property & Adversarial Test Plan  
17. Independent Verification Oracles  
18. Physical, Manufacturing or Financial Validation Protocol  
19. Acceptance Criteria (`AC-01`–`AC-12` & Release Level Mapping)  
20. Failure Modes, Rollback & Recovery Procedures  
21. Observability, Audit Logging & Telemetry  
22. Explicit Non-Goals & Scope Guardrails  
23. Downstream Unlocks  
24. Definition of Done Checklist
