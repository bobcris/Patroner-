## 1. Core Verification Philosophy (`R2.1`)

1. **Passing Unit Tests Are Necessary But Never Sufficient:** An implementation can pass unit tests while harboring 17× error-bound violations (`DEF-M00-01`), interior cusp bypasses (`DEF-M00-02`), and cross-tenant omission vulnerabilities (`DEF-M00-04`).
2. **Four-Tier Numerical Assurance Separation (`Correction 04`):** High-precision `mpmath` (`mp.dps = 80`) reference values are never conflated with **certified numerical error bounds** (`Method C1` chord/control-polygon enclosure, `Method C2` Higham polynomial inner-product bound, `Method C3` Bernstein-form + `mpmath.iv` interval enclosure).
3. **Complete-Interval Offset Proof vs. Heuristics (`Correction 05`):** Finite point grids (`65-point Gauss–Lobatto`) are treated solely as fast pre-screening heuristics; acceptance under `AC-03` and `AC-05` requires complete parameter-interval ($t \in [0, 1]$) verification via Bernstein polynomial positivity bounds and certified interval subdivision (`ADR-009`).
4. **Three-Level Release Separation (`Correction 03`):** Every acceptance dimension explicitly defines what is required for **Level A (Engineering & Controlled Pilot Entry for `M09`)**, **Level B (`M09` Pilot Exit Acceptance from real operational evidence)**, and **Level C (`M10` Enterprise & Institutional Scale Release)**.

## 3. Summary of the Three Release Governance Levels (`Correction 03`)

| Release Level | Target Milestone Gate | Scope & Purpose | Prohibited Conflation |
| :--- | :--- | :--- | :--- |
| **Level A — Engineering & Controlled Pilot Entry Release** | Entry gate to **`M09` (Controlled Commercial Pilot)** | Certifies that software architecture, multi-tenant security, certified geometry/offset/grading/marker math, calibrated materials, simulation benchmarks, physical sample approvals at $\ge 2$ workshops, 8-role offer contracts, multi-currency ledger, and single-region operational recovery are verified safe to run the capped ($\le 50$ unit) pilot. | Must **never** be represented as enterprise scale readiness (`Level C`), and does **not** require `M10`-only capabilities (BYOK KMS, multi-region active-active failover, celebrity recoupment waterfalls). |
| **Level B — `M09` Controlled Pilot Exit Acceptance** | Exit gate of **`M09`** (Unlocks **`M10`**) | Certifies that real physical garments were ordered, cut, sewn, inspected, shipped, worn by real customers, and financially settled with $\ge 95\%$ first-pass POM QC yield, bounded fit return rates, and $0$ minor-unit cash-to-ledger variance. | Software unit tests or synthetic simulations (`Level A`) may **never** substitute for real physical, customer, workshop, and financial pilot evidence (`Level B`). |
| **Level C — Enterprise & Institutional Scale Release** | Exit gate of **`M10`** | Certifies repeatable multi-brand/celebrity Brand Studio operations, enterprise partner APIs, automated GDPR crypto-shredding at scale, BYOK KMS, and multi-region disaster recovery (`RPO <= 5 min`, `RTO <= 30 min`). | Governed strictly post-`M09`. |
