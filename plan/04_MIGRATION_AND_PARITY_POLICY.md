## 1. Governing Migration Rule: No Mechanical Translation

The existing TypeScript codebase (`src/engine/*`) contains browser-era shortcuts (`.toFixed(2)` intermediate point quantization in `math.ts`, `.toFixed(3)` arc-length rounding in `curve-projection.ts`, 3-point offset sampling in `piece-production-sheet.ts`, and bodice-only grading in `pattern-grader.ts`). Therefore:
1. **Never translate TypeScript into Python mechanically line-by-line.**
2. **Every Python module must be engineered from its governing specification (`v5.16` and Dossiers 01–16)** and verified against both independent high-precision reference oracles and certified mathematical error bounds (`Section 3`).
3. **Never preserve a legacy TypeScript bug merely to achieve byte-for-byte output equality.** Intentional defect fixes (`DEF-M00-01`–`DEF-M00-06`) are validated against **Class B Normative Fixtures** under an incremented `engineVersion`.

## 3. Four-Tier Numerical Assurance Framework (`Correction 04` & `ADR-009`)

A high-precision reference calculation (`mpmath` at `mp.dps = 80`) or a small difference between two successive quadrature rules ($|\mathcal{I}_{2n} - \mathcal{I}_n|$) is **not** automatically a rigorous mathematical error certificate. Blueprint Revision 2.1 strictly separates four distinct numerical concepts across all specifications and tests:

1. **Concept 1 — High-Precision Reference Value ($X_{\text{ref}}$):**
   - An independent high-precision approximation computed in Python `mpmath` (`mp.dps = 80` decimal digits) used as an adversarial testing oracle in CI (`M00.4`). It detects implementation bugs and cancellation drift, but does not by itself constitute a proof of interval enclosure at runtime.
2. **Concept 2 — Floating-Point Implementation Error ($E_{\text{impl}} = |X_{\text{fp64}} - X_{\text{exact}}|$):**
   - The actual error in the IEEE 754 `binary64` (`float64`) runtime value caused by floating-point representation (`u = 2^{-53} \approx 1.11 \times 10^{-16}`), intermediate arithmetic roundoff, and numerical discretization/quadrature truncation.
3. **Concept 3 — Certified / Rigorously Justified Numerical Error Bound ($B_{\text{cert}}$):**
   - A mathematically defensible upper bound computed alongside $X_{\text{fp64}}$ that guarantees $X_{\text{exact}} \in [X_{\text{fp64}} - B_{\text{cert}}, X_{\text{fp64}} + B_{\text{cert}}]$.
   - **Prohibition:** Never claim a certified bound merely because $|\mathcal{I}_{2n} - \mathcal{I}_n|$ is small (which can fail on oscillatory or cusp-adjacent integrands).
   - **Approved Certification Methods (`ADR-009`):**
     - **Method C1 (Convex-Hull / Control-Polygon Enclosure for Bézier Arc Length):** By the variation-diminishing and convex-hull properties of Bernstein polynomials, on any cubic Bézier sub-segment $\mathbf{B}_i$, the chord length $L_{\text{chord}, i} = \|\mathbf{P}_3 - \mathbf{P}_0\|$ is a **strict mathematical lower bound** and the control-polygon length $L_{\text{poly}, i} = \sum_{j=0}^{2} \|\mathbf{P}_{j+1} - \mathbf{P}_j\|$ is a **strict mathematical upper bound**:
       $$\sum_i L_{\text{chord}, i} \le L_{\text{exact}}(\mathbf{B}) \le \sum_i L_{\text{poly}, i}$$
       Combined with directed IEEE 754 outward rounding (`math.ulp` padding of $4 u L_{\text{poly}, i}$ per segment), $B_{\text{cert}} = \frac{1}{2}\sum_i (L_{\text{poly}, i} - L_{\text{chord}, i}) + \delta_{\text{fp64}}$ is a **100% mathematically rigorous enclosure certificate**!
     - **Method C2 (Exact Polynomial Integration + Higham Floating-Point Error Bound for Green's Area):** For lines and cubic Béziers, Green's integral $\frac{1}{2}\oint (x\,dy - y\,dx)$ is an **exact algebraic polynomial** of degree $\le 5$ in the control points (zero quadrature truncation error!). shifting coordinates by the contour centroid $\mathbf{c}$ and applying Higham's forward error bound $\gamma_k = \frac{k u}{1 - k u}$ to the inner-product summation yields a **strict mathematical upper bound** $B_{\text{cert, area}} = \gamma_n \sum_i |A_i|_{\text{abs}}$.
     - **Method C3 (Bernstein Basis Positivity + IEEE 1788 Interval Arithmetic `mpmath.iv` for Curvature, Offsets & Intersections):** Expressing polynomial inequalities in the Bernstein basis on $[0, 1]$ and evaluating coefficients in outward-rounded interval arithmetic (`mpmath.iv`) provides a **rigorous proof over the entire continuous interval $t \in [0, 1]$**.
4. **Concept 4 — Domain Acceptance Tolerance ($\tau_{\text{domain}}$):**
   - The engineering/manufacturing specification threshold required for garment validity (`AC-05`, `AC-06`, `AC-10`). A computation passes iff:
     $$E_{\text{impl}} \le B_{\text{cert}} \le \tau_{\text{domain}}$$
