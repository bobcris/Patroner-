## 1. Governing Migration Rule: No Mechanical Translation

The existing TypeScript codebase (`src/engine/*`) contains browser-era shortcuts (`.toFixed(2)` intermediate point quantization in `math.ts`, `.toFixed(3)` arc-length rounding in `curve-projection.ts`, 3-point offset sampling in `piece-production-sheet.ts`, and bodice-only grading in `pattern-grader.ts`). Therefore:
1. **Never translate TypeScript into Python mechanically line-by-line.**
2. **Every Python module must be engineered from its governing specification (`v5.16` and Dossiers 01–16)** and verified against independent reference enclosures and certified mathematical error bounds (`Section 3`).
3. **Never preserve a legacy TypeScript bug merely to achieve byte-for-byte output equality.** Intentional defect fixes (`DEF-M00-01`–`DEF-M00-06`) are validated against **Class B Normative Fixtures** under an incremented `engineVersion`.

## 3. Five-Concept Numerical Assurance, `Method C1` Downgrade & Tri-State Verification (`Corrections A, B, C, D` & `ADR-009`)

### 3.1 Explicit Triangle Inequality & Five-Concept Separation (`Correction A`)
A high-precision reference calculation (`mpmath` at `mp.dps = 80`) or a small difference between two successive quadrature rules ($|\mathcal{I}_{2n} - \mathcal{I}_n|$) is **not** automatically a rigorous mathematical error certificate. For any exact mathematical value $X_{\mathrm{exact}}$, production `float64` output $X_{\mathrm{float64}}$, and independent reference value $X_{\mathrm{ref}}$, the error obeys the explicit triangle inequality:

$$|X_{\mathrm{float64}} - X_{\mathrm{exact}}| \;\le\; \underbrace{|X_{\mathrm{float64}} - X_{\mathrm{ref}}|}_{E_{\mathrm{obs}}} \;+\; \underbrace{|X_{\mathrm{ref}} - X_{\mathrm{exact}}|}_{\le \, B_{\mathrm{ref}}}$$

The second term $|X_{\mathrm{ref}} - X_{\mathrm{exact}}|$ **must never be silently assumed to be zero**. Blueprint `R2.1.1` enforces five distinct concepts across all documents and persisted `NumericalVerificationRecord` manifests (`ADR-009 §2.2–§2.4`):
1. **Concept 1 — High-Precision Reference Result ($X_{\mathrm{ref}}$):** Independent `mpmath` (`mp.dps = 80`) or rational calculation.
2. **Concept 2 — Observed Implementation-to-Reference Discrepancy ($E_{\mathrm{obs}} = |X_{\mathrm{float64}} - X_{\mathrm{ref}}|$):** Measured difference between `float64` runtime output and $X_{\mathrm{ref}}$.
3. **Concept 3 — Certified Reference-to-Exact Enclosure ($B_{\mathrm{ref}} \ge |X_{\mathrm{ref}} - X_{\mathrm{exact}}|$):** Rigorous bound on the reference error itself (via `fractions.Fraction` where $B_{\mathrm{ref}}=0$, outward-rounded `mpmath.iv` interval radius, or validated Krawczyk root brackets). **If $|X_{\mathrm{ref}} - X_{\mathrm{exact}}|$ is not rigorously bounded, the result must be labeled `HIGH_PRECISION_NUMERICAL_REFERENCE` (`EMPIRICAL_ESTIMATE`), never `CERTIFIED_ENCLOSURE`.**
4. **Concept 4 — Certified Implementation-to-Exact Error Bound ($B_{\mathrm{cert}} \ge |X_{\mathrm{float64}} - X_{\mathrm{exact}}|$):** Derived either from a direct outward-rounded runtime enclosure $[\underline{X}, \overline{X}] \ni X_{\mathrm{exact}}$ or via $B_{\mathrm{cert}} = E_{\mathrm{obs}} + B_{\mathrm{ref}}$ when $B_{\mathrm{ref}}$ is certified.
5. **Concept 5 — Engineering Acceptance Tolerance ($\tau_{\mathrm{domain}}$):** Domain threshold requiring $B_{\mathrm{cert}} \le \tau_{\mathrm{domain}}$.

### 3.2 Approved Enclosures vs. Downgraded Engineering Estimates (`Correction B`)
- **`Method C1-Est` (`Adaptive Gauss–Legendre Quadrature Discrepancy` — Downgraded to `CONSERVATIVE_ENGINEERING_ESTIMATE`):**
  - The formula $E_{\mathrm{est}}(L) = \sum_{k=1}^M (16.0 \cdot |I_{16,k} - I_{8,k}| + 32 u_{64} I_{16,k}) + M u_{64} L_{\mathrm{total}}$ at depth $d \le 12$ is classified strictly as a **`CONSERVATIVE_ENGINEERING_ESTIMATE`** (`ADR-009 §3.1`), **never** a certified bound or mathematical proof, because a fixed constant $S_{\mathrm{safety}} = 16.0$ does not bound the Peano kernel remainder near complex branch points of $\sqrt{x'(z)^2 + y'(z)^2}$.
- **`Method C1-Cert` (`De Casteljau Chord / Control-Polygon Convex-Hull Interval Enclosure` — `CERTIFIED_ENCLOSURE`):**
  - By the triangle and Minkowski integral inequalities on the quadratic Bernstein derivative basis (`ADR-009 §3.2`), on every cubic Bézier sub-segment $\mathbf{B}_k$, the chord length $L_{\mathrm{chord}, k} = \|\mathbf{P}_{k,3} - \mathbf{P}_{k,0}\|_2$ and control-polygon length $L_{\mathrm{poly}, k} = \sum_{j=0}^2 \|\mathbf{P}_{k,j+1} - \mathbf{P}_{k,j}\|_2$ satisfy $\sum_k L_{\mathrm{chord}, k} \le L_{\mathrm{exact}}(\mathbf{B}) \le \sum_k L_{\mathrm{poly}, k}$ unconditionally. Evaluating these sums with outward interval rounding in `mpmath.iv` yields the certified enclosure $[\underline{L}_{\mathrm{chord}}, \overline{L}_{\mathrm{poly}}] \ni L_{\mathrm{exact}}$ and certified bound $B_{\mathrm{cert}}(L) = \max(|L_{\mathrm{float64}} - \underline{L}_{\mathrm{chord}}|, |\overline{L}_{\mathrm{poly}} - L_{\mathrm{float64}}|)$.
- **`Method C2` (`Exact Polynomial Green's Theorem Integration + Higham Rounding Bound` — `CERTIFIED_ENCLOSURE`):**
  - Exact rational reference ($B_{\mathrm{ref}} = 0$ in `fractions.Fraction`) + centroid-shifted `float64` bilinear form with Higham forward rounding bound $\gamma_{64} \sum |c_{ij}| |x_i y_j|$.
- **`Method C3` (`Bernstein Basis Positivity + Outward-Rounded Interval Arithmetic mpmath.iv` — `CERTIFIED_ENCLOSURE`):**
  - Encloses polynomial ranges over $[0, 1]$ using Bernstein convex-hull bounds and `mpmath.iv` outward rounding (`ADR-009 §4–§5`).

### 3.3 Six-Category Offset Failure Taxonomy & Tri-State Outcomes (`Corrections C & D`)
- **Six Independent Offset Failure Categories (`ADR-009 §4.2`):**
  1. `REGULARITY_MARGIN_VIOLATION` ($0 < 1 + s\,d\,\kappa(t) < \varepsilon_{\mathrm{margin}}$, not a proven cusp),
  2. `ACTUAL_ZERO_SPEED_CUSP` ($Q(t^*)=0$ or $1 + s\,d\,\kappa(t^*) = 0$ proven via root isolation),
  3. `TANGENT_REVERSAL` ($1 + s\,d\,\kappa(t) < 0$ or $\tilde{\mathbf{O}}'(u)\cdot\mathbf{B}'(t(u)) < 0$ proven via strictly negative upper bound),
  4. `LOCAL_OFFSET_SELF_INTERSECTION` (verified 2D intersection root within local concave/miter neighborhood),
  5. `GLOBAL_CONTOUR_SELF_INTERSECTION` (verified 2D intersection between non-local contour segments; never inferred from local curvature alone),
  6. `INCONCLUSIVE_VERIFICATION` (interval straddles threshold at budget limit).
- **Tri-State Verification Outcomes (`ADR-009 §5.1`):** Every interval verification returns **`CERTIFIED_VALID`**, **`CERTIFIED_INVALID`**, or **`INCONCLUSIVE`**. `INCONCLUSIVE` is never misreported as a confirmed defect, triggers the 4-step escalation protocol (`ADR-009 §5.2`), and fails closed at downstream release gates (`AC-03`, `AC-05`, `AC-10`).
