## 3. Mandatory `R2.2` Technical Audit Corrections Integrated into Blueprint

### 3.1 Fix 1 — `AG-15` Krawczyk / Interval-Newton Existence & Uniqueness + Validated Interval AABBs
* **Defect Identified in `R2.1.2-R1` / `Checkpoint 13A`:** Naive point-sampled bounding boxes or unconstrained local Newton roots cannot prove non-local offset self-intersection rigorously without risking missed intersections or false rejections.
* **Mandatory `R2.2` Standard (`c1_cert_oracle.py`, verified in `d1a7940`):**
  1. **Validated Interval AABBs:** Each non-adjacent sub-arc $(s_1, s_2)$ of the offset contour $\mathbf{O}(t)$ must be enclosed in conservative interval bounds obtained from exact rational Bernstein control points or `mpmath.iv` directed-outward sub-interval evaluations (`validatedIntervalAabbs`), guaranteeing zero clipping false negatives.
  2. **Rigorous Krawczyk Contraction Proof:** On candidate overlapping sub-domain boxes $X = [t_1] \times [t_2] \subset [0, 1]^2$, define residual $\mathbf{F}(t_1, t_2) = \mathbf{O}_i(t_1) - \mathbf{O}_j(t_2)$ and Jacobian $J(\tau_1, \tau_2) = [\mathbf{O}_i'(\tau_1), -\mathbf{O}_j'(\tau_2)]$. Compute preconditioned operator $Y = J(m)^{-1}$ at box midpoint $m$ and Krawczyk map:
     $$K(X) = m - Y \mathbf{F}(m) + (I_2 - Y J(X))(X - m).$$
     A unique simple transverse intersection inside $X$ is **certified only if**:
     $$K(X) \subseteq \operatorname{int}(X) \quad \text{and} \quad \|I_2 - Y J(X)\|_\infty < 1.$$
  3. **Fail-Closed `INCONCLUSIVE` / `UNRESOLVED` Handling:** If the box width reaches machine tolerance or contraction fails across unresolved overlapping pairs (e.g., tangential contour touch without strict transverse contraction), the oracle **must fail closed** with `verification_outcome = "INCONCLUSIVE"` and `failure_category = "INCONCLUSIVE_VERIFICATION"`, blocking any production clearance.

### 3.2 Fix 2 — Honest `mpmath.iv` Assurance & Operational Limitations vs. `python-flint` & `DecimalInterval`
* **Mandatory `R2.2` Disclosure (No Over-Claiming):**
  * **`mpmath.iv` (`1.4.1`) is NOT formal IEEE 1788-2015 compliant:** It is a pure-Python arbitrary-precision binary interval arithmetic context lacking IEEE 1788 decoration tags (`com/dac/def/trv/ill`), verified in Workstream A (`d1a7940`) as useful for arbitrary-precision outward-rounded certification **only when governed by strict wrapper discipline**:
    1. *Interval squaring dependency (`u*u` vs. `u**2`):* `u*u` introduces interval dependency widening and, across zero-straddling intervals, can include negative values unless tight power semantics (`u**2` -> $[0, \dots]$) or affine/Bernstein enclosures are used.
    2. *Non-dyadic float literal trap:* Passing raw Python `float` literals (e.g., `0.1`, `1/3`) directly into `iv.mpf` inherits prior binary64 rounding error; all inputs must enter from exact integers or `fractions.Fraction` converted via directed rational bounds (`Fraction -> [iv.mpf(num)/iv.mpf(den)]` under outward interval context).
    3. *Silent `[-inf, +inf]` division-by-zero & negative-`sqrt` traps:* Wrapper must explicitly inspect divisor intervals for $0 \in D$ and radicands for $\inf R < 0$, halting or branching cleanly before silent widening contaminates downstream boxes.
    4. *Runtime Cost (~64x slower than C-backed `arb`):* Observed Workstream A benchmarks on Linux `x86_64` (`Python 3.12.16`): `mpmath.iv + Fraction` median **`0.9903 ms`** / curve (`6201.39 ms` for 200k population checks), whereas secondary C-backed reserve **`python-flint 0.9.0` (`arb` + `fmpq`)** achieved median **`0.0154 ms`** / curve (`2756.43 ms` for 200k checks), and tertiary fallback **`DecimalInterval` (`prec=50, 102`) + `Fraction`** achieved median **`0.1141 ms`** / curve (`3567.21 ms` for 200k checks).
  * **Operational Consequence:** `mpmath.iv + Fraction` qualifies cleanly within the `50 ms` per-curve oracle budget, while `python-flint` (`arb`) remains the qualified high-throughput C-extension reserve candidate for `DEC-13 Stage 2` review at `Gate Auth-2`.
